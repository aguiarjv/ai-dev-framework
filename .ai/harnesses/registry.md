# Harness Registry

## Rules

- Prefer registered harnesses over ad hoc validation commands.
- If no harness matches the task, use project-standard commands and consider creating one with `create-harness`.
- Keep harnesses deterministic and safe for local execution.
- Record prerequisites, inputs, expected success, and expected failure so reviewer and tester agents can interpret results correctly.
